# LP CVR・可読性チェックスキル

このLPの目的は「初回体験(トライアル)プランへの申込を最大化すること」。デザインの見た目の良し悪しだけでなく、実際にスマホで読んだときに離脱せず申込みまで辿り着けるかを評価する。

## 手順

1. 対象LPのdevサーバーを起動する(`npm run dev` 等)。ポートが競合する場合は別ポートで起動してよい。**`--host 0.0.0.0` は使わず、`127.0.0.1` など外部公開しないホストを指定する。**
2. Playwright MCPでブラウザをスマホ幅(375〜390px相当、例: 390×844)にリサイズし、トップから実際にアクセスする。
3. 各セクション(`id`属性があればそれを使って`scrollIntoView`、なければ`scrollTo`でスクロール位置を指定)ごとにスクリーンショットを撮り、上から順に目視確認する。`fullPage`の縮小スクリーンショットは全体構成の把握用、個別セクションは等倍のビューポートスクリーンショットで文字量・余白を確認する。
4. 下記チェック観点ごとに、該当箇所(セクション名・できれば行番号)を指摘しながら評価する。

## チェック観点

### 1. 文字量・画像量のバランス(スマホ)
- テキストだけのセクションが何画面分も連続していないか(目安: 写真・図解なしのテキストセクションが3画面分以上連続したら要注意)。
- 1セクションの文字量が多すぎて、スマホで何度もスクロールしないと読み終わらないセクションがないか。
- 画像は「意味のある画像」か(ただの装飾ではなく、悩み・施術・信頼感を伝える画像になっているか)。

### 2. 配置バランス・視覚階層
- 余白が詰まりすぎていないか、逆に間延びしていないか。
- 似たデザインのカードが連続しすぎて単調になっていないか(例: 似た白カードが何個も続く)。
- 見出し・本文のサイズ差でメリハリがついているか。

### 3. ストーリー展開
- 悩み共感 → 解決策の提示 → 自院が選ばれる理由(差別化) → 具体的な証拠(医師の経歴・安全体制等) → 価格 → 行動(CTA) の流れが自然か。
- 途中で話が飛んだり、同じ主張の繰り返しで間延びしていないか。
- 読み手が離脱しそうな「不安が解消されないまま次のセクションに進んでしまう箇所」がないか。

### 4. 「通院よりも自宅で受けたい」と思わせる訴求(訪問サービス特有)
- 通院の負担(移動・待ち時間・身支度)と、自宅で受けるメリット(時間の使い方・プライバシー・快適さ)の対比が、具体的なビジュアル・数字で伝わっているか。
- 価格差・時間差など、比較の「数字」が目立つ位置にあるか。
- 「自宅だからこそ得られる体験」(自分の時間として使える、人目を気にしない等)が十分に描写されているか。

### 5. CTA(申込導線)
- CTAの配置頻度は適切か(長いLPで何画面もCTAなしで続いていないか)。
- ボタンの文言は、ただの「予約する」ではなく、行動のハードルを下げる言葉になっているか(例: 「まずは話を聞いてみる」等)。
- 固定フッターCTAなど、常に申込導線が見える工夫があるか。

## 出力形式

- 良い点を先に簡潔に挙げる。
- 上記5観点ごとに、具体的な箇所(セクション名・できれば行番号)と改善案を箇条書きで示す。
- 問題がない観点は「特になし」と明記し、無理に指摘を作らない。
- 優先度(今すぐ直すべき/余力があれば)を明示する。

## 医療広告ガイドラインとの関係

このスキルはCVR・可読性に特化したチェックであり、医療広告ガイドライン適合性のチェックは対象外(`lp-reviewer`エージェント、または各プロジェクトのCLAUDE.mdを参照)。CVR改善の提案が誇大広告・比較優良広告にならないよう、改善案を出す際は最低限の目配りはすること。
